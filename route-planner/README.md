# route-planner: маршрутизатор по сети городов

Консольная программа на Java, которая по карте городов и дорог находит маршруты между городами.

## Какую задачу решает

Дана сеть городов, соединённых двусторонними дорогами с известной длиной. Программа отвечает на три вопроса:

1. **Каков кратчайший по длине маршрут** из города A в город B и какие города на пути?
2. **Каков маршрут с наименьшим числом дорог** (меньше всего участков, длина не важна)?
3. **Сколько в сети изолированных регионов**, между которыми проехать нельзя?

Если маршрута не существует (города в разных регионах), программа сообщает об этом, а не падает.

## Запуск

Нужен JDK 17 или новее.

```bash
./gradlew run                                   # демонстрация на примере карты
./gradlew run --args="Москва Воронеж"           # свой маршрут
./gradlew test                                  # тесты
```

В Windows: `gradlew.bat`. Если `gradlew` нет в проекте, откройте папку в IntelliJ IDEA (она создаст wrapper)
или выполните `gradle wrapper`. Для запуска из IDEA: `Main.java` → зелёная стрелка у `main`.

Пример вывода:

```
Городов: 10, регионов: 2

=== Москва -> Воронеж ===
Кратчайший: Москва -> Рязань -> Липецк -> Воронеж (580 км)
Меньше всего дорог: Москва -> Тула -> Липецк -> Воронеж (3 дороги)

=== Москва -> Хабаровск ===
Маршрута не существует
```

Расстояния в примере условные, это демонстрационные данные.

## Структура проекта

```
src/main/java/routeplanner/
  Graph.java        граф: список смежности, добавление городов и дорог, проверки
  Edge.java         дорога (куда ведёт, длина)
  Route.java        результат: длина и список городов
  RouteFinder.java  алгоритмы: Дейкстра, BFS, подсчёт регионов
  Main.java         консольная демонстрация
src/test/java/routeplanner/
  GraphTest.java        тесты структуры графа
  RouteFinderTest.java  тесты алгоритмов
```

Структура данных (`Graph`) отделена от алгоритмов (`RouteFinder`): граф ничего не знает о поиске путей,
а алгоритмы работают с графом только через `neighbors()`.

## Использованные структуры данных и алгоритмы

| Что                               | Где                              | Зачем                                               |
|-----------------------------------|----------------------------------|-----------------------------------------------------|
| Граф, список смежности            | `Graph`: `Map<String, List<Edge>>` | хранить сеть дорог                                  |
| Алгоритм Дейкстры                 | `RouteFinder.shortestPath`       | кратчайший маршрут по длине                         |
| Приоритетная очередь (куча)       | `PriorityQueue` в Дейкстре       | всегда брать город с наименьшим известным расстоянием |
| Обход в ширину (BFS), очередь     | `RouteFinder.fewestStops`        | маршрут с наименьшим числом дорог                   |
| Обход в ширину по всем вершинам   | `RouteFinder.countRegions`       | компоненты связности                                |
| Восстановление пути по цепочке `previous` | `restorePath`            | выдать сами города, а не только длину               |
| `HashMap` / `HashSet`             | во всех алгоритмах               | расстояния, предки, посещённые города за O(1)       |

## Сложность

V - число городов, E - число дорог.

| Операция                  | Время            | Память  |
|---------------------------|------------------|---------|
| `addCity`, `addRoad`      | O(1)             | O(1) на элемент |
| `shortestPath` (Дейкстра) | O((V + E) log V) | O(V)    |
| `fewestStops` (BFS)       | O(V + E)         | O(V)    |
| `countRegions`            | O(V + E)         | O(V)    |
| Хранение самого графа     | -                | O(V + E) |

Пояснение к Дейкстре: каждая дорога может добавить в очередь одну запись (O(log E) = O(log V) на вставку),
а каждая запись извлекается один раз. Память «O(V)» указана для самого алгоритма сверх графа;
в очереди может быть до O(E) устаревших записей (см. ниже про отложенное удаление), поэтому в худшем случае O(E).

## Обоснование ключевых архитектурных решений

### Решение 1. Список смежности, а не матрица смежности

Дорожная сеть **разрежена**: у города несколько дорог, а не дороги в каждый другой город.
Для 10 000 городов матрица содержала бы 10 000 × 10 000 = 10⁸ ячеек (около 400 МБ для `int`), хотя реальных дорог
может быть порядка 30 000. Список смежности занимает O(V + E), то есть сотни килобайт.

Главная операция всех трёх алгоритмов - «перебрать соседей города». В списке смежности это O(степень города),
в матрице - всегда O(V), то есть обход всего графа превратился бы в O(V²). Матрица выигрывает только в проверке
«есть ли дорога между A и B за O(1)», но эта операция нам не нужна.

### Решение 2. Два разных алгоритма, а не один

Обход в ширину (BFS) и Дейкстра отвечают на **разные** вопросы, и подменить один другим нельзя:

- BFS находит путь с минимальным **числом** дорог. Он корректен только когда все дороги «равны».
- Дейкстра учитывает **длину** дорог.

Пример из теста `fewestStopsDiffersFromShortestPath`: дорога `A–D` длиной 100 напрямую и цепочка
`A–B–C–D` по 1 каждая. BFS выберет `A → D` (одна дорога, 100 км), Дейкстра выберет `A → B → C → D` (три дороги, 3 км).
Поэтому в проекте оба алгоритма: пользователю иногда важна длина, иногда - число пересадок.

### Решение 3. Почему Дейкстра даёт правильный ответ

Условие: длины дорог неотрицательны. Для этого `Graph.addRoad` отклоняет отрицательную длину исключением.

Идея доказательства: когда город извлекается из очереди, его расстояние окончательное. Допустим, существовал бы
более короткий путь. Он проходит через ещё не обработанный город, расстояние до которого в очереди не меньше текущего
(иначе его бы извлекли раньше). Но дорога дальше по пути имеет длину ≥ 0, и общая длина не может стать меньше.
Противоречие. Именно поэтому можно остановиться, как только извлечён целевой город (ранний выход в `shortestPath`).
С отрицательными дорогами это рассуждение ломается.

### Решение 4. Мелкие, но важные детали

- **Отложенное удаление из очереди.** В `PriorityQueue` Java нет операции «уменьшить приоритет», а `remove(Object)`
  работает за O(n). Вместо этого при улучшении расстояния добавляется новая запись, а старая при извлечении
  пропускается (`current.distance() > dist.get(...)`). Это сохраняет O(log V) на операцию.
- **Итеративные алгоритмы, без рекурсии.** Рекурсивный DFS на цепочке из 100 000 городов вызывает
  `StackOverflowError`. Тест `longChainDoesNotOverflowStack` проверяет это.
- **`long` для расстояний.** Сумма нескольких длин в `int` может переполниться. Тест `distancesDoNotOverflowInt`
  использует две дороги по `Integer.MAX_VALUE`.
- **`Optional` для «пути нет».** Недостижимость - нормальный результат, а не ошибка, поэтому это не исключение
  и не магическое значение `-1`. Неизвестный город, напротив, ошибка вызывающего кода, и бросается
  `IllegalArgumentException`.

## Рассмотренные и отклонённые альтернативы

| Альтернатива | Почему отклонена |
|--------------|------------------|
| **Матрица смежности** | O(V²) памяти и O(V) на перебор соседей, дорожная сеть разрежена (см. решение 1) |
| **Беллман-Форд** | O(V·E) медленнее Дейкстры; его преимущество - отрицательные веса, а длина дороги отрицательной быть не может |
| **Флойд-Уоршелл** | O(V³) по времени и O(V²) по памяти; считает расстояния между всеми парами, а нужна одна пара |
| **A\*** | Нужна эвристика (координаты городов), что усложняет модель; на небольшой сети выигрыш незначителен |
| **BFS для поиска кратчайшего по длине** | Некорректен на дорогах разной длины (пример в решении 2) |
| **Перебор всех путей (DFS с возвратом)** | Экспоненциальное время; число простых путей растёт катастрофически |
| **Жадный выбор «ближайшего соседа»** | Не гарантирует кратчайший путь: локально короткая дорога может вести в тупик |
| **Дейкстра на массиве вместо кучи** | O(V²); лучше только на очень плотных графах, а у нас граф разрежен |
| **Рекурсивный DFS для компонент связности** | Риск переполнения стека на длинных цепочках |

## Тесты

```bash
./gradlew test
```

HTML-отчёт: `build/reports/tests/test/index.html`. При первом запуске Gradle скачивает JUnit из Maven Central,
нужен интернет.

Всего 27 тестов (JUnit 5).

**Основной сценарий:**
- кратчайший маршрут выбирает самую лёгкую цепочку, а не самую короткую по числу дорог;
- результат симметричен (A→D и D→A одной длины);
- кратчайший путь до соседа может идти в обход, если так короче;
- BFS находит путь с минимумом дорог;
- BFS и Дейкстра дают разные ответы там, где должны.

**Пограничные случаи:**
- маршрут из города в самого себя (длина 0, путь из одного города);
- недостижимый город (другой регион, изолированный город) → пустой результат;
- неизвестный город → исключение;
- пустой граф (поиск → исключение, регионов 0);
- один город = один регион;
- параллельные дороги (выбирается короче);
- дороги нулевой длины;
- отрицательная длина, пустое и `null` название города → исключение;
- цепочка из 100 000 городов (нет переполнения стека);
- сумма длин больше `Integer.MAX_VALUE` (нет переполнения);
- соединение двух регионов уменьшает их число и делает маршрут возможным.
